# img2bin_indexqoi 使用说明

索引 QOI V2（静态调色盘）压缩取模工具：在 QOIF 式数据流之上增加两项能力——**跳转索引**（从任意索引点"空降"解码局部区域，不必从头解到尾）与**静态调色盘**（编码时统计出收益最高的 0~64 个颜色，压成单字节 op）。解码零 RAM 字典、零哈希计算，调色盘可原地读 flash，适合下位机按行/按区域刷屏的场景。

设计实测参考（`rgb565`，相对无压缩的体积率，V1 → V2）：照片类 22.5% → 16.4%，GUI 界面 12.3% → 5.9%，图标 6.7% → 4.3%。

## 快速开始

- **双击运行**：第一次双击自动创建 `input`、`output` 文件夹；把图片放进 `input` 再双击一次（默认 `rgb565`、大端、索引间隔 = 图片宽度）
- **拖拽**：把图片或文件夹拖到 `img2bin_indexqoi.exe` 上
- **命令行**：

```powershell
.\img2bin_indexqoi.exe --input .\demo.png --output .\out --format argb8888 --index-interval 128
```

## 参数

| 参数 | 说明 |
| --- | --- |
| `--index-interval <count>` | 像素索引间隔，`1..65535`（本工具特有；默认 = 图片宽度） |
| `--input <file-or-dir>` | 输入文件或目录（默认 `<exe_dir>\input`） |
| `--output <dir>` | 输出目录（默认 `<exe_dir>\output`） |
| `--format <name>` | 单一像素格式（默认 `rgb565`） |
| `--formats <all\|f1,f2,...>` | 一次输出多种格式（`all` 自动跳过 `a8/a4/a2/a1`） |
| `--little-endian` | 小端输出（默认大端） |
| `--bg-color <RRGGBB>` | 非 Alpha 格式的透明区域先与该背景色混合（默认 `000000`） |
| `--manifest` | 在输出目录写 `img2bin_indexqoi-manifest.json` 运行清单（默认关闭） |
| `--info` / `--list-formats` / `--help` | 元数据 JSON / 格式清单 / 帮助 |

每写出一个文件，stdout 报告一行体积率（压缩后 payload / 同格式无压缩 payload，通用头 6 字节两边不计入）：

```text
Wrote out\gui_rgb565_indexqoi_be_128x64.bin (1288 bytes, payload 1282 / raw 16384 = 7.8%)
```

退出码：`0` 成功；`1` 参数错误；`2` 输入错误；`3` 编码错误；`4` 写入错误；`5` 内部错误；`6` 批处理部分失败。错误详情以单行 JSON 写到 stderr（字段：`code`、`exit_code`、`message.zh_cn/en`、`file`、`detail`、`stage`）。

### 索引间隔怎么选

- 默认 = 图片宽度（每行一个索引点），配合"按行刷新"场景最自然
- 间隔越小：跳转粒度越细，但索引区越大、段首打断压缩越频繁，体积率变差
- 间隔越大：体积率更好，但跳转后需要顺序解码的像素更多
- 全图只顺序解码一次的场景可以给一个很大的间隔

## 输出文件结构

### 文件命名（机器接口）

```text
<原图名>_<像素格式>_indexqoi_<be|le>_<宽>x<高>.bin
```

字节序**不存在于文件内部**，只体现在文件名的 `be|le` 段（或由工程约定提供）。

### 6 字节通用资源头

所有 `.bin` 都以 6 字节头开始，之后紧跟 indexQOI payload：

```text
byte0   = 资源类型，恒 0x00（图片）
byte1   = 格式码：高 nibble 压缩算法，低 nibble 像素格式
byte2-3 = 宽，恒大端
byte4-5 = 高，恒大端
```

- 本工具算法 nibble：`0x4`（全表：`raw=0x0 rle=0x1 imprle=0x2 qoi=0x3 indexqoi=0x4 qoif=0x5`）
- 像素格式 nibble：`RGB565=0x0 RGB888=0x1 RGB332=0x4 ARGB8888=0x5 ARGB6666=0x6 ARGB4444=0x7 ARGB8565=0x8 ARGB2222=0x9 RAGB5155=0xA`（`0x2/0x3/0xF` 保留不用）
- 宽、高、索引间隔上限均为 65535

## 像素来源与预处理（编码语义）

1. 输入图片统一解码为每像素 8bit 的 `R,G,B,A`；没有 Alpha 通道的输入（如 JPG）视为 `A=255`
2. **非 Alpha 目标格式**（`rgb888/rgb565/rgb332`）先把透明区域与背景色混合（整数运算，除法向下取整）：

   ```text
   out = (src * A + bg * (255 - A) + 127) / 255
   ```

3. 8bit 通道量化到 n 位：`Qn = (v8 * ((1 << n) - 1) + 127) / 255`
4. 例外：`RAGB5155` 的 1bit Alpha 用阈值 `A1 = (A8 >= 128) ? 1 : 0`
5. 带 Alpha 的目标格式不做背景混合，RGB 通道直接量化原始值

## 彩色格式打包规则（9 种）

像素顺序恒为**从左到右、从上到下**。大端布局如下；**小端 = 把单个像素的全部字节整体反转**；单字节格式（`rgb332/argb2222`）两种模式输出一致。

| 格式 | 字节数 | 大端布局（bit 高→低） | `0xFE` 后接 | `0xFF` 后接 |
| --- | --- | --- | --- | --- |
| `argb8888` | 4 | `A8, R8, G8, B8` | 3 字节 RGB（同端序） | 4 字节完整像素 |
| `argb6666` | 3 | `A[5:0]R[5:4]`，`R[3:0]G[5:2]`，`G[1:0]B[5:0]` | 不使用 | 3 字节完整像素 |
| `argb4444` | 2 | `A[3:0]R[3:0]`，`G[3:0]B[3:0]` | 不使用 | 2 字节完整像素 |
| `argb2222` | 1 | `A[1:0] R[1:0] G[1:0] B[1:0]` | 不使用 | 1 字节完整像素 |
| `argb8565` | 3 | `A8` + `(R5<<11)|(G6<<5)|B5` 大端 | 2 字节 RGB565（同端序） | 3 字节完整像素 |
| `rgb888` | 3 | `R8, G8, B8` | 不使用 | 3 字节完整像素 |
| `rgb565` | 2 | `(R5<<11)|(G6<<5)|B5` 大端 | 不使用 | 2 字节完整像素 |
| `rgb332` | 1 | `(R3<<5)|(G3<<2)|B2` | 不使用 | 1 字节完整像素 |
| `ragb5155` | 2 | `(R5<<11)|(A1<<10)|(G5<<5)|B5` 大端 | 不使用 | 2 字节完整像素 |

注意：本工具的 `0xFE`（剥透明度全量）**只用于 `argb8888` 和 `argb8565`**——只有这两种格式剥掉 Alpha 后能省 1 字节；其余格式（含无 Alpha 格式）全量一律用 `0xFF`。

`a8/a4/a2/a1` 仅 `img2bin_raw` 支持，本工具显式点名会报错（退出码 1）。

## indexQOI payload 布局

```text
[14字节索引头][u16索引区][u24索引区][u32索引区][静态调色盘][QOI数据流]
```

### 14 字节索引头（恒大端）

```text
byte0     = 头长度，恒 0x0E（兼作版本标识；旧版 V1 的 0x0D 视为不支持）
byte1-2   = 图片宽度
byte3-4   = 图片高度
byte5-6   = 像素索引间隔
byte7-8   = u16 索引区字节长度
byte9-10  = u24 索引区字节长度
byte11-12 = u32 索引区字节长度
byte13    = 调色盘条目数，0..64（0 = 无调色盘，不必填满；大于 64 视为损坏流）
```

### 索引区

每 `间隔` 个像素为一"段"，段首像素即索引点；索引点总数 = `⌈宽×高 ÷ 间隔⌉`。每个索引值 = 该段首 op 相对 **QOI 数据流起点**的字节偏移（从 0 起）：

- 偏移 `≤ 0xFFFF` 存 u16（2 字节）；`≤ 0xFFFFFF` 存 u24（3 字节）；更大存 u32（4 字节）
- u16/u24/u32 三区依次排列，区内按段序排列，均为大端（高字节在前）
- 第 k 个索引点属于哪个区，由它的偏移值大小决定；由于偏移随段序单调递增，三个区天然按段序衔接

### 静态调色盘

紧跟 u32 索引区之后。每项为一个**完整原始格式像素**（含 Alpha），字节数与字节序和 `0xFF` 全量像素完全相同。调色盘全局有效：不随位置变化，解码过程中永不修改。

```text
调色盘起点   = 14 + u16区长 + u24区长 + u32区长
QOI数据流起点 = 调色盘起点 + 条目数 × 每像素字节数
```

## QOI 数据流规则

所有比较与差分运算都在**量化后的目标格式通道值**上进行（例如 `rgb565` 用 R5/G6/B5），不是 8 位 RGBA。解码只需一组前像素状态，无字典、无哈希。

### op 一览（首字节区分）

| op | 名称 | 语义 |
| --- | --- | --- |
| `0x00..0x3F` 且 `op < 条目数` | 调色盘 op | `当前像素 = 调色盘第 op 项`（含 Alpha，可表达透明度变化）；`op ≥ 条目数` 视为损坏流 |
| `0x40..0x7F` | DIFF | `dr=((op>>4)&3)-2, dg=((op>>2)&3)-2, db=(op&3)-2`；当前 = 前像素分量 + 差值，Alpha 沿用前像素 |
| `0x80..0xBF` + 1 字节 | LUMA | `dg=(op&0x3F)-32`；第 2 字节 `b`：`dr=dg+((b>>4)&0xF)-8, db=dg+(b&0xF)-8`；Alpha 沿用前像素 |
| `0xC0..0xFD` | RUN | 把前像素重复输出 `(op&0x3F)+1` 次（1..62） |
| `0xFE` + RGB 字节 | 剥透明度全量 | 仅 `argb8888`（3 字节）/`argb8565`（2 字节），Alpha 沿用前像素 |
| `0xFF` + 完整像素 | 原始全量 | 按格式字节数读入完整像素（含 Alpha） |

- 查到的调色盘条目要解包成通道状态再输出，它同时成为后续 DIFF/LUMA 的"前像素"
- DIFF/LUMA 结果超出该格式通道位宽范围视为损坏流
- 每个 op 输出的像素同时更新前像素状态
- 数据流没有结束码：解码按像素数到数即停；提前耗尽 = 截断，产满后仍有剩余字节 = 多余数据

### 段首（索引点）规则

- 段首前编码器必然已强制结束 RUN（**RUN 不跨段**）
- 段首 op 只可能是两种：**调色盘 op** 或 **`0xFF` 原始全量**——两者都不依赖任何上文，因此从索引点空降解码自包含，无状态需要复位（调色盘全局有效）

### 空降解码步骤

读取第 k 个像素附近的区域（`interval` = 索引间隔）：

```text
index_slot = 目标像素序号 / interval
base_pixel = index_slot * interval
offset     = 第 index_slot 个索引值
cursor     = QOI数据流起点 + offset
```

从 `cursor` 起按上表规则解码，第一个解出的像素就是 `base_pixel`，每段解 `interval` 个像素（末段不足按剩余），到数即停。

## 编码器规则（两遍法，保证输出唯一，可对拍）

### 第一遍：统计选盘

无调色盘地模拟逐像素 op 分类（分类规则与第二遍除查盘外完全一致），统计每个颜色（量化域 `r,g,b,a` 四元组）若进盘可省的字节数：

| 该颜色出现一次的场合 | 省 |
| --- | --- |
| 索引点（`0xFF` 全量 → 1 字节） | 每像素字节数 |
| LUMA 可压（2 字节 → 1 字节） | 1 |
| DIFF 可压（1 字节 → 1 字节） | 0（不计） |
| RUN 像素 | 0（不查盘） |
| 全量、Alpha 未变、`argb8888` | 3 |
| 全量、Alpha 未变、`argb8565` | 2 |
| 全量、其他情况（含 Alpha 变化） | 每像素字节数 |

**净收益 > 每像素字节数**（调色盘条目自身的存储成本）的颜色才有资格进盘；按收益降序取前 64 项；收益相同时按 32 位**有符号**颜色键 `(r<<24)|(g<<16)|(b<<8)|a` 降序。调色盘可以为 0 项。

### 第二遍：正式编码

逐像素优先级（命中即产出）：

1. 索引点？→ 强制结束 RUN、记录索引；盘命中出单字节调色盘 op，否则 `0xFF` 全量
2. 与前像素相同？→ 累计 RUN（累计到 62 或图像最后一个像素时写出）
3. 否则先写出未完的 RUN；颜色在盘中？→ 单字节调色盘 op（不区分透明度是否变化）
4. Alpha 未变？→ DIFF → LUMA → 全量（`argb8888/argb8565` 用 `0xFE`，其余 `0xFF`）
5. Alpha 变化 → `0xFF` 全量

## 使用示例

```powershell
.\img2bin_indexqoi.exe --format argb8888
.\img2bin_indexqoi.exe --format argb8888 --index-interval 512
.\img2bin_indexqoi.exe --formats rgb565,argb8888 --index-interval 128 --manifest
```
