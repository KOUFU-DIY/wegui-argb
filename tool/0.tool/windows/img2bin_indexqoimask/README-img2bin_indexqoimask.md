# img2bin_indexqoimask 使用说明

索引QOI_MASK 压缩取模工具：面向 **A8 透明蒙版**（图标、按键、UI 蒙版）的无损/可选量化压缩格式，为 PFB 逐切片渲染场景设计。四项能力：

- **按行随机访问**——每行都有独立的字节偏移索引，可直接跳到任意行解码；
- **MCU 流式解码**——逐字节读取，单行解码 RAM 为 0（边解边写 PFB），无字典重建、无整图缓冲；
- **解码器极简**——tag 高 2 位判别，四分支 switch + 一个 `0xFF` 特判，纯整数加减；
- **可选有损量化**——8/7/6/5 bit 四档，量化发生在编码域，解码输出规则确定。

本工具**仅支持 `a8` 格式**（默认格式即 `a8`，无需 `--format`）。实测参考（48×48 真 8bit 抗锯齿图标 ×12，相对裸 A8 payload）：全无损约 49%、6bit 约 36%、5bit 约 31%；层次少的量化型图标可达 24%~40%。

## 快速开始

- **双击运行**：第一次双击自动创建 `input`、`output` 文件夹；把图片放进 `input` 再双击一次（默认 `a8`、6bit 量化）
- **拖拽**：把图片或文件夹拖到 `img2bin_indexqoimask.exe` 上
- **命令行**：

```powershell
.\img2bin_indexqoimask.exe --input .\icon.png --output .\out --quantize-bits 8
```

## 参数

| 参数 | 说明 |
| --- | --- |
| `--quantize-bits <5\|6\|7\|8>` | Alpha 量化位数（本工具特有；默认 `6`，`8` 为严格无损） |
| `--input <file-or-dir>` | 输入文件或目录（默认 `<exe_dir>\input`） |
| `--output <dir>` | 输出目录（默认 `<exe_dir>\output`） |
| `--format <name>` | 像素格式；本工具只接受 `a8`（默认即 `a8`，通常无需传） |
| `--formats <all\|f1,f2,...>` | `all` 自动滤除到只剩 `a8`；显式点名其他格式会报错 |
| `--little-endian` | 只影响文件名的 `le` 段；payload 内多字节字段恒大端，输出字节不变 |
| `--bg-color <RRGGBB>` | 对本工具无效（只取 Alpha 通道，没有颜色可混合），仅为与其他工具保持一致而接受 |
| `--manifest` | 在输出目录写 `img2bin_indexqoimask-manifest.json` 运行清单（默认关闭） |
| `--info` / `--list-formats` / `--help` | 元数据 JSON / 格式清单 / 帮助 |

每写出一个文件，stdout 报告一行体积率（压缩后 payload / 裸 A8 payload，通用头 6 字节两边不计入）：

```text
Wrote out\keys_a8_indexqoimask_be_48x48.bin (838 bytes, payload 832 / raw 2304 = 36.1%)
```

退出码：`0` 成功；`1` 参数错误；`2` 输入错误；`3` 编码错误；`4` 写入错误；`5` 内部错误；`6` 批处理部分失败。错误详情以单行 JSON 写到 stderr（字段：`code`、`exit_code`、`message.zh_cn/en`、`file`、`detail`、`stage`）。

### 量化档位怎么选

| 档位 | 适用 | 实测（keys ×12） |
| --- | --- | --- |
| `--quantize-bits 8` | 严格无损需求 | 49% |
| `--quantize-bits 6`（默认） | UI 图标/按键，视觉近无损 | 36%（ALPHA 兜底归零，编码行为最稳） |
| `--quantize-bits 5` | 大面积柔边蒙版，建议逐图目检 banding | 31% |
| `--quantize-bits 7` | 价值有限，保留不推荐 | 43% |

小图不适用：行索引 + 字典的固定开销在 16px 字形级别会吃掉全部收益（实测 74%~137%），该尺寸建议用裸 2bpp/4bpp 位图。

## 输出文件结构

### 文件命名（机器接口）

```text
<原图名>_a8_indexqoimask_<be|le>_<宽>x<高>.bin
```

本格式无字节序维度（payload 内多字节字段恒大端），`be`/`le` 输出逐字节一致，文件名段仅随 `--little-endian` 开关变化。

### 6 字节通用资源头

所有 `.bin` 都以 6 字节头开始，之后紧跟索引QOI_MASK payload：

```text
byte0   = 资源类型，恒 0x00（图片）
byte1   = 格式码，恒 0x6B：高 nibble 0x6 = 索引QOI_MASK 压缩，低 nibble 0xB = A8
byte2-3 = 宽 w，恒大端
byte4-5 = 高 h，恒大端
```

宽、高上限均为 65535（建议 ≤ 32767）。

## 像素来源与量化域（编码语义）

1. 输入图片统一解码为每像素 8bit 的 `R,G,B,A`；没有 Alpha 通道的输入（如 JPG）视为 `A=255`。只取 Alpha 通道，忽略颜色与 `--bg-color`
2. 量化位数 `q ∈ {8,7,6,5}`。`q < 8` 时源 Alpha 取高 q 位：

   ```text
   v = a >> (8 - q)
   ```

3. **流内一切数值——行首字节、字典项、ALPHA 后接字节——均为 q 位域值**
4. 解码输出 8bit 时按高位复制扩展（保证 0→0、满量程→255、无系统偏差）：

   ```text
   out = (v << s) | (v >> (q - s))，s = 8 - q
   ```

5. `q = 8` 为严格无损（`v = a`，扩展为恒等）
6. DIFF/DELTA 差分在 q 位域进行，**不回绕**：编码器保证每一步中间值都落在 `[0, 2^q - 1]` 内，解码器直接加减；解出越界值即为损坏流

## payload 布局

通用头之后的 payload（多字节字段一律大端；宽高不在 payload 内，以通用头为准）：

```text
[标志位 1B][u16 行索引项数量 m 2B][u32 行索引项数量 2B]
[u16 行索引表 m×2B][u32 行索引表 (h−m)×4B]
[字典数量 n 1B][字典 n×1B][像素流]
```

| 字段 | 说明 |
| --- | --- |
| 标志位 | `b1:b0` 量化位数 q：`00`=8bit `01`=7bit `10`=6bit `11`=5bit；`b7..b2` 保留，必须为 0 |
| u16 行索引项数量 m | 大端 |
| u32 行索引项数量 | 大端；必须等于 `h − m`（解码器可校验） |
| u16 行索引表 | m 项 × 2B，大端 |
| u32 行索引表 | (h−m) 项 × 4B，大端 |
| 字典数量 n | 1B，`0..64`（0 = 无字典，INDEX 不可用） |
| 字典 | 每项 1B，存 q 位域值 |
| 像素流 | 各行数据 |

### 行索引与分表规则

- 每项 = 该行数据相对**像素流起点**的字节偏移（不是文件起点，也不是 payload 起点）
- **行去重**：内容完全相同的行（按量化后的行内容判定）只存一份数据，多行索引可指向同一偏移；解码任何一行都必须从行索引重新定位，不得假设行间数据连续
- **前缀分表**：m 取"偏移值仍 ≤65535 的最长行前缀"的行数；**第 m 行起（0 基）无论偏移大小一律进 u32 表**——行去重后偏移不随行号单调，按行序分表，不按偏移值分表
- 解码器取第 r 行：`r < m` 查 u16 表第 r 项，否则查 u32 表第 `r − m` 项

## 像素流

### 行结构

- 每行第 1 个字节 = 该行第 1 个像素的 q 位域原始值（**无 tag**），同时初始化 `prev`
- 其后为 tag 流，累计输出满 w 个像素立即结束（行末不做对齐、无结束符）
- **行完全独立**：`prev` 不跨行，RUN/DIFF 不得跨行

### tag 编码（高 2 位判别）

| tag | b7 b6 | b5..b0 | 产出 | 语义 |
| --- | --- | --- | --- | --- |
| INDEX | `0 0` | 6bit 字典下标（`< n`） | 1 像素 | `prev = 字典[下标]` |
| DIFF | `0 1` | d0：b5..b3，d1：b2..b0，各 3bit `[-4,+3]`（存储值 = d+4） | 2 像素 | `px1 = prev+d0`，`px2 = px1+d1` |
| DELTA | `1 0` | 6bit `[-32,+31]`（存储值 = d+32） | 1 像素 | `prev + d` |
| RUN | `1 1` | 6bit 计数 c ∈ `[0,62]` | c+1 像素（1..63） | 复制 `prev` |
| ALPHA | `1 1` | 计数 = 63（整字节恒 `0xFF`），后接 1 字节 q 位域原始值 | 1 像素 | 绝对值直设 |

- 每个 tag 处理完后 `prev` 更新为最后输出的像素值
- **行尾只剩 1 像素时不得使用 DIFF**
- 编码器约束：INDEX 下标必须 `< n`；DIFF/DELTA 不得产生越界中间值（无回绕）

### 编码器规则（确定性，保证输出唯一、可对拍）

逐像素贪心，命中即产出（`r` = 从当前位置起与 `prev` 相同的连续像素数，上限 63）：

1. `r ≥ 2` → 写 RUN（计数 `r−1`）
2. 否则若剩余 ≥ 2 像素且 `d0 = 当前−prev`、`d1 = 下一个−当前` 都在 `[-4,+3]` → 写 DIFF（覆盖 `r = 1` 且 d1 合法的情形，d0 = 0）
3. 否则若 `r = 1`（与 `prev` 相同的孤立像素、DIFF 不可用）→ 写 RUN（计数 0）
4. 否则若 `d = 当前−prev ∈ [-32,+31]` → 写 DELTA
5. 否则若当前值在字典中 → 写 INDEX
6. 否则 → 写 ALPHA（`0xFF` + 原始值）

### 字典（两遍法）

静态字典，随文件存储、解码过程中永不修改：

- **第一遍**：在无字典条件下按上述规则模拟编码全部**唯一行**（去重后），统计"RUN/DIFF/DELTA 均无法编码"（即将跌入 ALPHA）的像素值频次
- **入典门槛**：频次 ≥ 2 的值才有资格（每次 ALPHA→INDEX 省 1 字节，字典项自身占 1 字节，净收益 > 0）
- **排序**：频次降序，同频次按 q 位域值降序，取前 64 项；字典可以为 0 项
- **第二遍**：带字典正式编码。两遍的 op 分类完全一致（INDEX 与 ALPHA 都是"单像素、`prev` = 该像素值"，不影响 RUN/DIFF/DELTA 的判定），因此结果确定

## 解码参考流程

```text
解析头 → q、m、u32 数量、两张索引表、n、字典、像素流基址 base
取第 r 行：
  pos  = base + (r < m ? u16[r] : u32[r−m])
  prev = data[pos++]                     ; 输出 expand(prev)
  while 已输出 < w:
    b = data[pos++]
    b == 0xFF   : prev = data[pos++]                 ; 输出 1 像素
    b>>6 == 0   : prev = 字典[b & 0x3F]              ; 输出 1 像素
    b>>6 == 1   : d0 = ((b>>3)&7)−4; d1 = (b&7)−4    ; 输出 prev+d0、prev+d0+d1，prev 取后者
    b>>6 == 2   : prev += (b & 0x3F) − 32            ; 输出 1 像素
    b>>6 == 3   : 复制 prev（(b & 0x3F) + 1）次
expand(v)：q==8 ? v : (v<<s)|(v>>(q−s))，s = 8−q
```

校验建议（可选，用于验证器）：保留位非 0、`u32 项数 ≠ h−m`、字典数量 > 64、字典项/行首字节/ALPHA 后接字节超出 q 位域、INDEX 下标 ≥ n、DIFF/DELTA 越界、RUN/DIFF 超出行宽，均视为损坏流；行数据提前耗尽为截断。

## 边界与限制

- w、h ≤ 65535（建议 ≤ 32767）；像素流 ≤ 4 GB（u32 索引上限），前 64 KB 由 u16 表覆盖
- 最坏情况（无任何可压内容）≈ 2 B/像素 + 行首/索引/头开销；实测 UI 素材 24%~58%
- 小图（16px 字形级别）固定开销占比过高，不建议使用本格式

## 使用示例

```powershell
.\img2bin_indexqoimask.exe
.\img2bin_indexqoimask.exe --quantize-bits 8
.\img2bin_indexqoimask.exe --input .\icons --output .\out --quantize-bits 5 --manifest
```
