# bin2c

`bin2c` 用来把一个或多个输入目录中的 `.bin` 文件转换成 C 数组，支持三种输出模式：

- **合并模式（默认）**：所有 `.bin` 按顺序拼接成 `merged_bin.bin`，并生成 `merged_bin.c` / `merged_bin.h`，头文件带资源 ID 枚举、大小/地址宏，`.c` 中默认只有地址表；加 `--embed-data` 可把拼接后的数据额外嵌入为一个大数组
- **拆分模式（`--split`）**：每个 `.bin` 生成一个同名 `.c`（内含同名数组）和同名 `.h`；用 `--output-h NAME` 可改为把所有声明合并到单个 `.h`
- **组合模式（`--output-c NAME`）**：每个 `.bin` 转成各自同名的数组，全部合并到单个 `NAME.c`，同时生成 `NAME.h`（可用 `--output-h` 改名）；加 `--merge-bin` 可同时输出拼接后的 `NAME.bin`

## 当前目录结构

- `bin2c.exe`
  Windows 下直接运行的主程序。
- `input_bin/`
  放原始 `.bin` 资源文件。
- `output/`
  默认输出目录。
- `builder/`
  构建 `bin2c.exe` 的工程目录。

## 默认行为

直接双击或运行：

```cmd
bin2c.exe
```

程序会：

1. 自动创建 `input_bin` 和 `output` 目录（如果不存在）
2. 扫描 `input_bin` 中所有 `.bin` 文件
3. 按文件名排序后依次合并
4. 在 `output` 中生成：

```text
merged_bin.bin
merged_bin.c
merged_bin.h
```

## 命令行参数

```text
--input DIR
    输入 bin 文件目录，默认: input_bin
    可以重复传入多次来指定多个目录，
    处理时按传入的目录顺序分块，每个目录内部再按文件名排序

--output-path DIR
--output-dir DIR
    输出目录，默认: output

--split
    拆分模式：每个 .bin 生成各自的 .c 和 .h（不能与 --output-c 同用）

--output-c NAME
    组合模式：所有数组合并到单个 NAME.c

--output-h NAME
--output-header NAME
    头文件名（仅拆分/组合模式）：
    拆分模式下改为输出单个合并声明的 NAME.h（代替每文件 .h）；
    组合模式下用于重命名头文件（默认与 .c 同名）

--merge-bin
    组合模式下额外输出拼接后的 NAME.bin，
    头文件同时生成 XXX_ADDR 偏移宏和 MERGED_BIN_SIZE

--no-size-macro
    不生成 XXX_SIZE 宏（仅拆分/组合模式），
    数组声明/定义直接用字面量尺寸，
    例如 extern const unsigned char logo[20];
    大小可用 sizeof(logo) 在编译期获取

以下参数仅用于合并模式（默认模式）：

--output-name NAME
--output-base NAME
    输出文件名主体，默认: merged_bin

--embed-data
    把拼接后的数据额外嵌入 .c，生成一个大数组
    （默认 .c 中只有地址表，数据只在 .bin 里）

--array-name NAME
    配合 --embed-data，生成到 .c 中的大数组名，
    默认: g_merged_bin_data

--symbol-prefix NAME
    生成到 .h 中的类型名前缀，默认: bin
```

## 使用示例

默认输出：

```cmd
bin2c.exe
```

自定义输出文件名：

```cmd
bin2c.exe --output-name res_pack
```

自定义输出目录：

```cmd
bin2c.exe --output-path D:\temp\out
```

同时自定义输出目录和文件名：

```cmd
bin2c.exe --output-name res_pack --output-path D:\temp\out
```

把数据同时嵌入 `.c`（生成大数组）：

```cmd
bin2c.exe --embed-data
```

自定义数组名（配合 `--embed-data`）：

```cmd
bin2c.exe --embed-data --array-name g_res_data
```

多个输入目录（按传入顺序分块合并）：

```cmd
bin2c.exe --input font_bin --input img_bin
```

上例中 `font_bin` 里的文件排在前面，`img_bin` 里的文件排在后面，各自目录内部按文件名排序。

每个 bin 独立生成 `.c` + `.h`（拆分模式）：

```cmd
bin2c.exe --split
```

拆分模式但所有声明合并到一个头文件：

```cmd
bin2c.exe --split --output-h all_bins
```

所有数组合并到单个 `.c`（组合模式）：

```cmd
bin2c.exe --output-c res_pack
```

组合模式，重命名头文件并同时输出拼接后的 `.bin`：

```cmd
bin2c.exe --output-c res_pack --output-h resources --merge-bin
```

## 拆分模式（`--split`）

每个 `.bin` 独立转换成同名 `.c` 和 `.h`。例如输入 `logo.bin`、`font_16.bin` 会生成：

```text
logo.c      logo.h
font_16.c   font_16.h
```

每个 `.c` 内是一个以文件名命名的数组（小写），`.h` 中是大小宏和 `extern` 声明：

```c
/* logo.h */
#define LOGO_SIZE ((unsigned long)20)
extern const unsigned char logo[LOGO_SIZE];
```

```c
/* logo.c */
#include "logo.h"

const unsigned char logo[LOGO_SIZE] =
{
    ...
};
```

指定 `--output-h NAME` 后不再生成每文件 `.h`，改为输出单个 `NAME.h` 包含全部数组的声明，各 `.c` 统一 include 它。

加 `--no-size-macro` 可省掉 `XXX_SIZE` 宏，声明直接带字面量尺寸（大小用 `sizeof` 获取）：

```c
/* logo.h（--no-size-macro） */
extern const unsigned char logo[20];
```

## 组合模式（`--output-c NAME`）

所有 `.bin` 各自转成同名数组，依次合并进单个 `.c`：

```cmd
bin2c.exe --output-c res_pack
```

生成 `res_pack.c`（内含 `logo[]`、`font_16[]` 等全部数组）和 `res_pack.h`（全部数组的大小宏与声明）。头文件可用 `--output-h` 重命名。

加 `--merge-bin` 会同时输出按顺序拼接的 `res_pack.bin`，头文件末尾额外生成每个文件在合并镜像中的偏移宏和总大小：

```c
#define LOGO_ADDR ((unsigned long)0)
#define FONT_16_ADDR ((unsigned long)20)

#define MERGED_BIN_SIZE ((unsigned long)90)
```

组合模式同样支持 `--no-size-macro`（只去掉 `XXX_SIZE` 宏；`XXX_ADDR` 和 `MERGED_BIN_SIZE` 不受影响）。

## 合并模式（默认）生成文件说明

### 1. `.bin`

输出一个按顺序拼接后的二进制文件，例如：

```text
merged_bin.bin
```

### 2. `.c`

默认只生成地址表的定义（文件开头会 `#include` 对应的 `.h`），例如：

```c
/* This file was generated by bin2c. */
#include "merged_bin.h"

const unsigned long bin_addr_table[bin_COUNT] =
{
    0,   //IMG_A
    100, //IMG_B
};
```

加 `--embed-data` 后，会在地址表前额外嵌入拼接后的数据数组：

```c
const unsigned char g_merged_bin_data[...] =
{
    ...
};
```

### 3. `.h`

头文件开头会带自动生成说明：

```c
/* This file was generated by bin2c. */
```

并生成以下内容：

- 合并总大小宏 `MERGED_BIN_SIZE`
- 数据数组的 `extern` 声明（仅加 `--embed-data` 时生成）
- 资源 ID 枚举
- 资源大小宏定义
- 地址表 `unsigned long` 数组的 `extern` 声明（定义在 `.c` 中）
- 资源地址宏

示例：

```c
#define MERGED_BIN_SIZE ((unsigned long)300)

typedef enum
{
    IMG_A_ID = 0,
    IMG_B_ID = 1,
    bin_COUNT = 2
} bin_id_t;

#define IMG_A_SIZE ((unsigned long)100)
#define IMG_B_SIZE ((unsigned long)200)

extern const unsigned long bin_addr_table[bin_COUNT];

#define IMG_A_ADDR ((unsigned long)0)
#define IMG_B_ADDR ((unsigned long)100)
```

加 `--embed-data` 时，`MERGED_BIN_SIZE` 之后会额外生成数据数组的声明：

```c
extern const unsigned char g_merged_bin_data[MERGED_BIN_SIZE];
```

`bin_addr_table` 的顺序和 `XXX_ID` 的顺序一一对应。

注意：`bin_addr_table`（以及加 `--embed-data` 时的 `g_merged_bin_data`）的定义在生成的 `.c` 里，全程序只有一份。代码中如果用到这些符号，需要把生成的 `.c` 一起编译链接；如果数据烧写在外部 Flash、只需要偏移量，可以只 include `.h` 并使用 `XXX_ADDR` / `XXX_SIZE` 宏。

## 说明

- 单个输入目录时，文件按文件名排序后处理
- 多个输入目录时，按 `--input` 传入的目录顺序分块，每个目录内部再按文件名排序
- 不同目录中出现同名文件时，两个文件都会被处理，后出现的符号自动加 `_2`、`_3` 等后缀（例如 `LOGO` 和 `LOGO_2`；拆分/组合模式下数组名、输出文件名同步为 `logo_2`）
- 数组名由文件名生成：去掉扩展名、非字母数字字符转 `_`、数字开头前加 `_`；数组名用小写，宏用大写
- 合并模式下输出地址顺序和 ID 顺序保持一致
- 合并模式 `.c` 中默认只定义 `bin_addr_table`，加 `--embed-data` 时才有 `g_merged_bin_data`；只用 `XXX_ADDR` 等宏时可以只 include `.h`
- 如果输入目录中没有 `.bin` 文件，程序会提示后退出
