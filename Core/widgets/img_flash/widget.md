# img_flash

## 功能
外挂 Flash 图片控件，从外部存储流式读取图片资源并显示，当前支持 `IMG_RGB565`、`IMG_RGB565_INDEXQOI` 和 `IMG_ARGB8565_INDEXQOI`。

## 适用场景
- 大量图片放外部 Flash
- 片内空间不足但需要展示图片资源
- 图片资源与内置资源格式保持一致的场景

## 关键 API
- `we_flash_img_obj_init(...)`
- `we_flash_img_obj_set_opacity(...)`
- `we_flash_img_obj_set_pos(...)`

## 可调宏
在 `we_user_config.h` 中可覆盖：
- `WE_FLASH_IMG_CHUNK`：流式读取块大小，默认 128 字节（未压缩图半透明时分块读；不透明时整行直接读进 PFB）；也是索引 QOI 数据窗口的大小
- `WE_FLASH_IMG_IDX_WIN`：索引 QOI 行索引预取窗口，默认 64 字节
- `WE_FLASH_IMG_CACHE`：索引 QOI 读取缓存，默认 1；设 0 不占静态 RAM

## 读取策略（索引 QOI）
- 解码经两个窗口读外挂：行索引窗口一次预取后续多行的索引项，数据窗口缓存一段连续的数据流；请求落在窗口内直接取，不再发起外挂读取
- V3 的非去重行按行序紧挨存放，相邻行的索引与数据都会连续命中同一窗口
- 索引头（m16、调色盘条目数）在 init 时与资源头一次读出并存进对象，绘制时不再读；调色盘按图片地址缓存，同一张图不再每个 PFB 切片重读
- `WE_FLASH_IMG_CACHE = 1` 时读取状态放静态 RAM，跨切片、跨帧保留；`= 0` 时放栈上，只在单次绘制内有效
- 读取状态记下所属的外挂读取回调，多块屏接不同存储器时互不串用
- 模拟器实测 demo 15 连续 180 帧（240×240、PFB 2 行加 DMA 双缓冲即整屏 1 行切片）：外挂读取 19348 次、传输 2.05 MB；缓存关闭时 41001 次、4.54 MB

## 事件与行为
- 不处理输入：event_cb 为 NULL，命中测试跳过它，触摸落到背后的控件
- 主要通过外部 Flash 读取 + 普通重绘完成显示

## 注意事项
- 端口描述（`we_port_t`）必须提供 `storage_read`
- 图片头格式与片内图片资源一致
- 当前支持格式：`IMG_RGB565 / IMG_RGB565_INDEXQOI / IMG_ARGB8565_INDEXQOI`
- 缓存开启时约占 400 字节静态 RAM，数量与图片个数无关；单槽设计，多张外挂压缩图落在同一批行时会互相挤出，最坏情况等于缓存关闭
- 缓存假设外挂数据运行期只读；改写外挂 Flash 后需重新调用 `we_flash_img_obj_init`，初始化会清空读取缓存
- 索引 QOI 只支持 V3 流：索引头在 init 时校验，V2/V1 或损坏的流初始化直接失败
- 不透明未压缩图直接读进 PFB 行：端口的 `storage_read` 要能一次读整行（窗口宽 = 图宽时为整片）并写进显存

## 已完成的毕业优化
- 未压缩 RGB565 不透明时直接读进 PFB 行再原地拼像素，省掉栈上中转与逐像素乘法寻址；图宽等于窗口宽时整片一次读完（只脏图片本身时 23 行的图由 23 次读取降到 1~4 次）
- 索引头在 init 时读进对象（多存 m16 与调色盘条目数共 3 字节，格式字段改为 1 字节抵掉一部分），缓存未命中时只重读调色盘；demo 15 读取次数 22363 → 19348（缓存关闭 57224 → 41001），像素逐位不变
- RGB565 与 ARGB8565 两个索引 QOI 解码器合并为一个（按每像素字节数区分调色盘项长与 0xFF 载荷）
- RUN 分两段处理：先跳过裁剪左缘以外的部分，再连续填到右缘，不再逐像素判断
- 绘制窗口直接取内核收窄后的 `lcd->clip`，删掉不可能触发的包围盒相交判断
- 容器透明度级联后 <= 5 时整段跳过，不读外挂；`set_opacity` 值未变不重绘（原先每次调用都整图重读外挂）
- 读取状态按外挂读取回调区分归属；`set_pos` 改为内联包装
