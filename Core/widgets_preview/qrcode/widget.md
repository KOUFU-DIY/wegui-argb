# qrcode（preview 孵化区）

## 功能
二维码控件 + 内置独立编码器。`we_qrcode_set_text()` 内同步完成编码（byte mode / ECC M / 版本 1~4 自动选最小），位矩阵（位压缩，33×5 字节）拷入控件自身成员，多实例互不干扰。渲染为"底色一次整铺（含 4 模块静区）+ 暗模块逐行横向 run 合并 `we_fill_rect`"。控件宽高 = (模块数 + 2×4 静区) × module_px，编码成功后自动更新 `base.w/h`（先标脏旧区域再标脏新区域）。内容超容量时画"底色 + 对角圆头粗线叉"错误占位。

## 适用场景
- 设备信息/固件版本/序列号展示（配网页、说明书跳转）
- WiFi 配网字符串（`WIFI:T:WPA;S:...;P:...;;`）
- 短 URL / 支付码类静态内容（≤ 62 字节）

## 编码器支持范围（we_qr_encoder.c）
- 版本 1~4（21/25/29/33 模块），按内容长度自动选最小版本
- ECC 等级固定 **M**；模式固定 **byte mode**（8bit 直通，ASCII/任意字节）
- 容量：v1=14 / v2=26 / v3=42 / v4=62 字节（= 数据码字 − 2）
- Reed-Solomon：GF(256) 指数/对数表首次调用时生成（本原多项式 0x11D），生成多项式按 ECC 阶数现算（10/16/26/18）
- v4-M 为 2 个等长 RS 块（各 32 数据 + 18 ECC），已实现标准逐字节交织
- 掩码 0~7 全部实现；**惩罚分仅算规则 1**（行/列连续同色 ≥5 记 3+(len−5) 分），选出的掩码合法可解码，但可能与完整评估器（规则 1~4）的选择不同
- 格式信息 15bit 打表（M × 8 掩码，含 0x5412 异或）；版本 ≤6 无版本信息块
- 纯整数、零 malloc、无 GUI 依赖（可脱离工程单独编译做向量自测）

## 正确性验证方式（已做 / 未做）
已做（独立 gcc 测试程序，`#include` 编码器源码直查内部状态）：
1. "HELLO" 的数据码字与**手工推算**的 16 字节向量逐字节比对（覆盖模式头/长度域/终止符/0xEC-0x11 补齐）
2. RS 数学自检：对每个块的 数据‖ECC 多项式求 α^0..α^(deg−1) 全部 syndrome，必须全零（独立于编码路径的代数验证）
3. 结构自检：三角 finder 图案、timing 交替、固定暗模块、两份格式位一致且等于所选掩码的表值
4. 全链路回读：按格式位读回掩码 → 去掩码 → 测试文件内独立重写的蛇形序提取码字 → 与编码器输出比对 → 解析模式/长度/数据还原原文
5. 容量边界：14/15/26/27/42/43/62/63 字节的版本跳变与拒绝

未做：真实扫码枪/手机摄像头扫描验证（模拟器环境不可达，毕业前必须补）。

## 关键 API
- `we_qrcode_obj_init(obj, lcd, x, y, module_px)` —— module_px 钳制 2~6；初始无内容按 v1 尺寸 (21+8)×module_px 显示纯底色面板
- `we_qrcode_set_text(obj, str)` —— 返回 0/-1；内容与当前一致直接返回不重编码；失败转错误占位（尺寸不变）
- `we_qrcode_set_colors(obj, dark, light)` —— 暗模块色 / 底色，双色均未变直接返回
- `we_qrcode_set_invert(obj, 0/1)` —— 仅交换前景/底色映射；反色码依赖扫码端容错，产品慎用
- `we_qrcode_obj_delete(obj)` —— 无动画节点，内联转调 `we_obj_delete`

## 渲染模型与成本
- 1 次整铺 + 每行若干次 run 合并 `we_fill_rect`（v3 典型 ~200 段），全部整数
- 位矩阵读取为位移+与操作（`we_qr_bit_get` 内联）
- 错误占位用 `we_draw_line_round` 两条对角线（现成 AA 原语）

## 事件与行为
- 装饰性控件：event_cb 恒返回 0，输入穿透
- 所有 setter 值未变时直接返回，不触发重绘
- 无 set_pos_cb：几何全部由 base.x/y 推导，`we_obj_set_pos` 默认移动逻辑即正确

## 注意事项
- 编码器工作区为文件级 static（矩阵 2×33×33 + 码字缓冲 ≈ 2.4KB）：**不可重入、非线程安全**；控件位矩阵为实例成员，编码完成后与工作区无关
- `set_text` 是同步重编码：v4 全流程（8 掩码试评）约数十万次整数操作，UI 线程内可接受但不宜每帧调用
- 超长内容（> 62 字节）不缓存文本，两个不同的超长串之间切换不会重复标脏（视觉相同，均为叉占位）
- 控件按 (row, col) 存位、屏幕按 y/x 渲染，镜像语义已与规范对齐（finder 三角在左上/右上/左下）

## 毕业前需优化
- **必须**：真机/手机摄像头实扫验证（v1~v4、两个 demo 串、反色、各 module_px）
- 掩码惩罚分补齐规则 2（2×2 同色块）、规则 3（1:1:3:1:1 仿 finder 序列）、规则 4（明暗占比），与标准评估器对齐
- 编码器 static 工作区（≈2.4KB）在 MCU 上应改为调用方提供的临时缓冲或与其他大缓冲复用（如 PFB 空闲期借用），并评估 byte-per-module 矩阵换位压缩工作区
- `set_text` 同步编码耗时在 M0 上需实测；必要时拆分为多帧渐进编码（timer 驱动）
- 支持 alphanumeric mode（大写字母+数字场景容量可提升 ~40%）与 ECC 等级可选（L/Q/H）
- 脏矩形：整控件标脏可接受（内容变化本来就是全刷），但颜色/反色切换可考虑跳过静区
- run 合并可进一步升级为"行间相同 run 布局合并"（相邻行图案相同时合并成高 2×module_px 的矩形）
