# glowring（preview 孵化区）

## 功能
透明渐变色环：在 size×size 包围盒内画一圈内切的单色环带（默认绿色），
透明度沿圆周做 **0 → 255 → 0 的镜像对称渐变**：起点角 `angle` 处全透明，
对面（angle + 180°）全不透明。剖面默认为 **余弦**（`WE_GLOWRING_PROFILE 1`），
即"穿过圆心的 SVG 线性渐变投到圆周上"的精确等价，两极各有一段平缓区；
可选三角剖面（角度严格线性）。`angle` 可任意旋转，环带宽度可指定。
另有 **双色**（透明端尾色沿剖面插到主色，对应两端 stop 颜色不同的渐变）与
**实心**（无渐变，整环 = 主色 × opacity，热路径跳过角度计算）两种模式。
纯显示控件，触摸穿透。

## 适用场景
- 旋转光环 / 呼吸光晕（设备工作中、扫描中、充电中）
- 环形"方向指示"（最亮处指向目标方向）
- 作为仪表 / 旋钮 / 头像的装饰外圈，叠在任意背景或控件之上

## 关键 API
- `we_glowring_obj_init(obj, lcd, x, y, size, band)` —— 色环内切 size×size；band = 0 自动取 size/5
- `we_glowring_set_angle(obj, 0..511)` / `we_glowring_rotate(obj, delta)` / `we_glowring_get_angle(obj)` —— 512 步制角度
- `we_glowring_set_color(obj, colour_t)` —— 环色（默认绿 RGB 40/220/110）
- `we_glowring_set_tail_color(obj, colour_t, enable)` —— 双色：透明端颜色（例：lime → 白）
- `we_glowring_set_solid(obj, 0/1)` —— 实心环（例：错误态的纯色红环）
- `we_glowring_set_shape(obj, r_q4_table, log2_n)` —— 形状表：相对透明端角度 → 外半径（Q4，2^n 项，
  项间线性插值，随 angle 旋转），内沿仍为正圆；NULL 卸下。"细圆 + 几个凸台"这类手绘风格的环用它 + 实心模式 + 旋转
  实现（demo 127 的左环就是这样画的），表可由 SVG 采样或公式生成（128 项即 256 B ROM）
- `we_glowring_set_radii(obj, r_out, r_in)` —— 在包围盒内运行期改半径（重算条带方案，新旧各标脏一次）
- `we_glowring_set_opacity(...)` / `we_glowring_set_pos(...)` / `we_glowring_obj_delete(...)`

## 可调宏
- `WE_GLOWRING_PROFILE`（1 余弦 = 线性渐变投影，默认；0 三角）
- `WE_GLOWRING_DEF_R / _G / _B`（默认环色 RGB888，默认 40/220/110）
- `WE_GLOWRING_MIN_BAND`（环带最小宽度，默认 4：内外各 1px 渐隐 + 2px 实体）
- `WE_GLOWRING_DITHER`（RGB565 有序抖动，默认 1；RGB888 / GRAY8 下无作用）

## 事件与行为
- `event_cb = NULL`：命中测试直接跳过，按压落到下层控件
- 角度 512 步制：0 = +X，128 = 正下方（屏幕 Y 向下），顺时针增；`angle` 是
  **透明端**（alpha 0）的位置，最亮处在 `angle + 256`
- 接入容器透明度级联（`we_opa_apply`），放在 group / slideshow 里随容器淡入淡出
- 单色样式（MONO）无自有调色板，渐变透明度经端口二值化后为硬边环，不额外适配

## 渲染与性能设计
热路径（`_gr_draw_cb`）全程整数，**零除法、零浮点、零乘法求距离**：
1. 窗口直接取内核已收窄的 `lcd->clip`（切片 ∩ 包围盒），只再与包围盒求一次交集作防御；
2. 每行 d² 用增量递推 `d² += 2dx + 1`，1 次加法完成环带内外判定；
3. 行内一旦踏入中心空洞（d² ≤ r_in²）立刻跳到关于中心对称的镜像点，空洞像素零遍历；
4. 角度 = 八分区折叠 → `t = 短边 × recip[长边] >> 8`（倒数表，Q16）→ `atan_tab[t]`
   （257 项 uint8 ROM 表）→ 象限展开，整圈最大误差 0.8 步（< 0.6°）；
5. alpha：余弦剖面 `((32768 − we_cos(Δ)) × 255 + 32768) >> 16`（Q15 查表，一次乘法），
   三角剖面 `|Δ| 折到 0..256` 后 `× 255 >> 8`；再乘内外边缘 1px 渐隐
   （入口预算 Q16 斜率，热路径只乘移）与整体不透明度（255 时整段跳过）；
   双色时颜色按同一剖面值在尾色 / 主色之间插值（每通道一次乘加）；
   实心时跳过 3~5 整段，alpha 恒 255；
   形状表时按 Δ 查两项做线性插值得外半径 r(Q4)，`(r² >> 8) − d²` ≤ 0 的像素直接丢弃，
   < 2r 的落在外沿 1px 渐隐带（斜率沿用基准外半径的 k_out，半径只差百分之几，看不出来），
   每像素约多 2 次乘法；实心 + 形状表时仍需算角度（为了查表），但省掉剖面与双色；
6. **自带混色**直写 pfb_gram：alpha 0..255 扩到 0..256 后 `(fg·a + bg·(256−a) + 舍入项) >> 8`，
   alpha = 255 恰好等于前景色，全程单调。不用内核 `we_store_blended_color` 的原因：
   它在 alpha ≥ 250 直接写前景色、中段又截断取整，长渐变在 255 附近会跳 2 级，
   肉眼可见一条高亮带（2026-10-06 实测：绿色 6 位值 53 → 55 跳过 54）；
7. RGB565 下舍入项默认取 4×4 Bayer 阈值（`WE_GLOWRING_DITHER`，均值 128），
   把每通道 32/64 级造成的 1 级宽台阶纹打散；索引用屏幕绝对坐标，与切片无关。

每个像素的结果只取决于它自己的屏幕坐标，与 PFB 切片高度、脏矩形切法无关
（切片无关性与 img_ex / label_ex 同一纪律）。

两张常量表由下面的 Python 片段生成（改表长时同步改 `_GR_R_MAX`）：
```python
import math
recip = [0] + [min(65535, round(65536 / k)) for k in range(1, 257)]
atan  = [round(math.atan(t / 256) * 512 / (2 * math.pi)) for t in range(257)]
```

## 脏区策略（本控件的核心优化点）
- 旋转 / 换色 / 改透明度只按 **宽度贴圆周的水平条带** 标脏环带，`WE_GLOWRING_DIRTY_RECTS`
  选 4 / 6 / 8 块（默认 4）：
  - 4 块：中心带 `[-m, m]` 左右各 1 块（挖掉空洞）+ 上下外带各 1 块；
  - 6 块：上下外带再切一刀 `t`，两段各取自己的贴圆宽度；
  - 8 块：`[m+1, t]` 整条落在空洞行内时也拆成左右两块；
  - 块数 ≥ 6 时同时评估更少块数的方案，取面积最小者（粗环下 8 块会自动退回 6 块）。
- 边界 `m / t` 与各带半宽在 **init 时穷举最优** 并存入对象（6 个 int16），运行期标脏零计算。
  搜索为 4 块 O(R)、6/8 块 O(R²)，内层用"递减平方根"摊销，r_out = 255 也只需几十 k 次简单运算。
- 包围盒四角与中心空洞里的下层控件、背景永远不参与刷新；移动时旧、新位置都按同一方案只标环带。
- 代价：每次变化占 4 / 6 / 8 个脏矩形槽（`WE_CFG_DIRTY_MAX_NUM` 默认 10）。用 8 块且多只环并存时
  管理器会触发"槽满→最小浪费合并"，收益打折，应把槽位提到 16 以上。
- 渲染结果与分块方式无关（每个像素只取决于自身坐标）：同一 demo 在 4 / 6 / 8 块下帧哈希完全一致。

提交面积（r_out 74 / r_in 44，环带真实像素 11104；DP 全局最优作参照）：

| 方案 | 面积 | 相对环带 | 与 DP 最优差 |
|---|---|---|---|
| 旧：包围盒 − 内接方孔（4 块） | 18779 | 1.69× | — |
| 4 块贴圆（默认） | 16376 | 1.47× | 0% |
| 6 块 | 15096 | 1.36× | 0% |
| 8 块 | 14946 | 1.35× | +2.6% |

细环（r 30/20）收益更明显：4 块 1.54×、6 块 1.42×、8 块 1.36×。flush 次数几乎不变
（2 行 PFB 下由高度决定），再往上加块数每 4 块只省 2~4%，已不划算。

## 注意事项
- 外半径上限 256px（倒数表长度），size > 514 时自动截断
- 环带最小 4px；band 过大时自动收到 r_out − 2，保证内半径 ≥ 2
- SVG 线性渐变（gradient 向量穿过圆心、两端落在环的两极）在圆周上
  就是余弦剖面，默认档已精确对应；三角剖面只作备选
- 每次旋转都会重绘整个环带（alpha 处处都变），无法再按角度局部标脏——
  这是渐变透明环的固有性质；要再降流量只能加大 PFB 行数减少 flush 次数
- 分块方案依赖 r_out / r_in，`set_radii` / `set_shape` 改半径时会重算，并在改前改后各按
  各自方案标脏一次（包围盒 size 在 init 固定，半径只能在其内变化）
- 48 MHz Cortex-M0 估算：渐变环（r 66..70）与形状表环（r 66..74）每帧环带像素各约 2.7k / 3.5k，
  每像素 45~55 周期，加上条带内非环带像素的 3 周期跳过，单帧渲染 3~4 ms；模拟器实测两种模式耗时持平

## 毕业前需优化
- 边缘 AA 用 d² 线性近似 d，环极细（band = 4）时渐隐略生硬，可改用每行一次
  整数 sqrt 求精确 d
- 可选：剖面形状参数（三角 / cos / 占空比），或 `we_glowring_set_span`
  只让渐变占圆周的一部分
